## 3. 転送の設定

`netlify.toml` に足す。Astro の `redirects` 設定は静的ビルドだと meta refresh の HTML になり 301 にならないので使わない。

```toml
# 受託ページの URL 変更（2026-11・経営ポータルの決定 0097）
[[redirects]]
  from = "/techplantstudio/*"
  to = "/services/:splat"
  status = 301

[[redirects]]
  from = "/techplantstudio"
  to = "/services/"
  status = 301
```

旧ページのファイルを dist に残すと転送より先にそちらが返るので、ページは移動（`git mv`）で消す。

## 4. 手順

1. ブランチを切る（`feat/services-url`）
2. §2.1 のとおりページを移し、リンクと表記を直す
3. `netlify.toml` に §3 を足す
4. `yarn build && yarn check:links` で内部リンクの切れが無いことを確かめる。`grep -rn techplantstudio src` が0件になることも確かめる
5. PR を作り、Netlify のデプロイプレビューで次を確かめる
   - `/techplantstudio/` → `/services/` に 301
   - `/techplantstudio/ip-minigame/` → `/services/ip-minigame/` に 301
   - `/techplantstudio/#contact` → `/services/#contact` に着き、フォームの位置に飛ぶ
   - `/techplantstudio`（末尾スラッシュなし）も 301 で着く
   - 問い合わせフォームのテスト送信で、`source_page` が `/services/` になる
6. 代表の確認のあとにマージして公開する
7. 公開後: Search Console で新 URL のインデックス登録を申請し、経営ポータルの計測の既定値と説明を直す（§2.2）

## 5. 戻し方

PR を revert すればページと転送の設定が両方戻る。301 はブラウザに覚えられるので、戻したあとも一部の人には新 URL が出続ける。そのため、新 URL のページも戻した後しばらく残す（`/services/*` → `/techplantstudio/:splat` の転送を足す）。

## 6. 代表の確認（2026-11-09）

1. 新しい URL は `/services/`（代表 11/09）
2. IP 向けページは `/services/ip-minigame/`。`/services/` の配下に入れる（代表 11/09）

4. 期限は ~11/20 のまま、公開作業は 11/09〜11/10 に終える（代表 11/09）
